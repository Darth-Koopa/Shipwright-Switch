## 修复 libultraship 4bpp 纹理除零崩溃（关键根因）
- 用户报告游戏崩溃，日志：`Fast::Interpreter::ImportTextureIA4` 处 `Exception: 0xc0000094`（整数除零），崩溃于 `interpreter.cpp:587` `height = sizeBytes / line_size_bytes`，RDX=0（除数为 0）。调用链：wide tex rect → GfxDpTextureRectangle → GfxDrawRectangle → GfxSpTri1 → ImportTexture → ImportTextureIA4。发生在 Deku Tree（Navi 的 C-Up 标签），CHI 模式按 Z 显示 C-Up 标签时触发。
- **根因**：4bpp 纹理经 `gDPLoadTextureBlock` 加载时，RENDERTILE 的 `line` 字段按 N64 宏 `(((width)*G_IM_SIZ_4b_LINE_BYTES)+7)>>3` 计算，而 `G_IM_SIZ_4b_LINE_BYTES = G_IM_SIZ_4b_BYTES = 0`（gbi.h:408-410），导致 `GfxDpSetTile` 设 `texture_tile[tile].line_size_bytes = line*8 = 0`。`ImportTextureIA4` 用该值做除法 → 除零。**这是引擎（libultraship fast interpreter）对 4bpp 纹理的固有 bug，与 CHI 自定义纹理无关**（ENG 模式用同样 IA4 C-Up 标签也会崩）。
- **修复**（`libultraship/src/fast/interpreter.cpp`）：在 `ImportTextureIA4`、`ImportTextureI4`、`ImportTextureCi4`、`ImportTextureImg` 四处，当 `line_size_bytes == 0` 时，从 tile 的 `lrs`/`lrt`（注意是 **float**，不能用 `>>`，用 `/ (float)(1<<G_TEXTURE_IMAGE_FRAC)`）反推 width/height，避免除零。注意 `lrs`/`lrt` 在 `interpreter.h:283` 是 `float`（S10.5 数值存为浮点），初次误用 `>>` 会报 C2296，已改浮点除法。
- 本次重建含 libultraship 改动，`BUILD_EXIT=0`，exe 时间戳 `2026/7/15 11:48:22`。
