## 修复 gNaviCUpCHITex 按 Z 崩溃（第三次）
- 现象：中文下按 Z 注视 → DX11 `UploadTexture` 抛 `ThrowIfFailed`（0xe06d7363），调用链 `gfx_tex_rect_wide_handler_custom → GfxDpTextureRectangle → ImportTextureRgba32 → UploadTexture`。
- 根因：`libultraship/src/fast/interpreter.cpp` 的 `ImportTextureRgba32` 用 `width = line_size_bytes/2`、`height = (size_bytes/2)/line_size_bytes` 推算宽高，这套公式是按 **16bpp** 写的（与 `ImportTextureRgba16`/`IA16` 同款）。对真正的 32bpp RGBA32 会算出错误宽高（或 line_size_bytes 未正确设置 → 尺寸=0），`CreateTexture2D` 传入非法尺寸抛异常。即：**该 TMEM 导入路径不支持 RGBA32 宽纹理矩形**。
- 修复：把 CHI 标签改用 **RGBA16 = `rgb5a1`**（16bpp，保留颜色）。文件 `gNaviCUpCHITex.rgba32.png`→`gNaviCUpCHITex.rgb5a1.png`；`z_parameter.c` 运行时 `G_IM_SIZ_32b`→`G_IM_SIZ_16b`。`ImportTextureRgba16` 同款公式可正确得到 48×16。
- OTR 后缀注意：OTRExporter(OTRExporter/OTRExporter/Main.cpp:221) 支持的 RGBA16 后缀是 **`rgb5a1`**（不是 `rgba16`/`rgba32` 之外的别名）。已构建确认 soh.o2r 中该纹理 1616 字节 = 48×16×2 + 80 头，格式正确。BUILD_EXIT=0。
- **重要经验**：custom CHI 纹理若要用于"宽纹理矩形/共享加载调用"且尺寸非标，优先用 `rgb5a1`(RGBA16) 或 `ia8`/`ia16` 等 16bpp 及以下格式；**避免用 `rgba32`**（解释器 ImportTextureRgba32 存在宽高计算 bug，会崩溃）。

## 修复 gNaviCUpCHITex 按 Z 崩溃（第四次，最终）
- 第三次改 rgb5a1(RGBA16) 后仍崩：`ImportTextureRgba16` 同样在 `UploadTexture` 抛 `ThrowIfFailed`。结论：**该 TMEM 导入路径对 RGBA 格式（RGBA16/RGBA32）在宽纹理矩形下都会崩**（RGBA32、RGBA16 均崩），而 `ia8`(Game Over CHI, 64x32)、`ia16`(FileSel CHI) 均正常。
- 最终方案：CHI 标签改用 **IA8**（灰度+alpha）。`gDPLoadTextureBlock(..., G_IM_FMT_IA, G_IM_SIZ_8b, 48, 16, ...)`；文件 `gNaviCUpCHITex.rgb5a1.png`→`gNaviCUpCHITex.ia8.png`。`ZAPD/ZTexture.cpp::ConvertBitmapToN64_GrayscaleAlpha8` 用 `pixel.r` 作强度、`pixel.a` 作 alpha，故源 PNG 需 R=G=B=亮度、A=透明（用 RGBA PNG 最稳妥）。已构建确认 soh.o2r 中该纹理 type=8(IA8)、48x16、768 字节，BUILD_EXIT=0。按 Z 不再崩溃。
- **关键经验**：Shipwright 的 fast 解释器对"宽纹理矩形 + 自定义 RGBA 纹理"有 bug，CHI 自定义纹理凡走 `gSPWideTextureRectangle`/`gDPLoadTextureBlock` 的，一律用 **IA 格式（ia4/ia8/ia16）**，不要用 RGBA(rgba32/rgb5a1)。OTRExporter 支持的自定义后缀见 Main.cpp:221（含 rgb5a1/ia8/ia16 等，无 rgba16）。
- **误删恢复技巧**：custom PNG 源被删时，可从 `soh.o2r` 还原——OTR 资源条目格式 = 64 字节头 + uint32 Type + uint32 Width + uint32 Height + uint32 ImageDataSize + ImageData；按 type 解码原始 N64 像素即可还原（RGBA16 即 RGBA5551）。

## 修复：GetItemIcon 全量替换遗留 ] 导致编译报错（2026-07-14 夜）
- **教训/根因**：上一步用 `replace_all` 把 `gItemIcons[` 换成 `GetItemIcon(` 时，只换了开括号 `[`→`(`，**遗留了所有对应的结尾 `]`**，生成 `GetItemIcon(itemId]` 这类非法语法。MSVC 报 C2143「缺少 ')' 在 ']' 前面」/C2059，遍布 z_message_PAL.c、z_parameter.c、z_kaleido_item/equipment/collect.c（共 24 处调用）。
- **修复**：逐个把每处 GetItemIcon 调用的**外层** `]` 改回 `)`（保留内层数组下标如 `[i]`、`buttonItems[N]` 不动）。
  - z_kaleido_item.c 3 处、z_kaleido_equipment.c 4 处、z_kaleido_collect.c 4 处、z_parameter.c 10 处（含 pauseCtx->equipTargetItem 与 buttonItems[0..7]）、z_message_PAL.c 4 处（memcpy+strlen 各 2）。
- **重要经验**：**替换函数/数组调用形式时，`[`→`(` 必须同时把配对的 `]`→`)`**；不能只做半边的全量替换。今后遇到 `name[expr]`→`func(expr)` 应逐调用点连同结尾一起改，或改后立即 grep `func\([^)]*\]` 自查。
